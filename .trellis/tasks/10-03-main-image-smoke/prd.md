# 主应用镜像真实启动与迁移检查

## 目标与授权

补齐构建后的主应用验证缺口：实际运行本次构建的 georelay:checked，保留默认 ENTRYPOINT/CMD，连接全新隔离 PostgreSQL，证明迁移和 HTTP 服务可用后才允许保存/发布。

用户最新交办明确授权本项实现与验证，要求不重问执行意图；本项不新增合并或生产部署授权。父任务的 beta/自动合并/失败 Bark 规划保留，其部署范围已确认为 GHCR 正式镜像/latest，不更新运行容器。本子任务作为独立可验收部分先实施。

## 范围与验收

- R1：在 ci.yml 两个原生架构的构建后、镜像 artifact 保存前加入同一启动脚本；失败阻断后续发布。
- R2：脚本使用传入的本次主镜像及 adapter Python 探测器，不覆盖主应用默认入口/命令；使用独立 internal 网络、临时 PostgreSQL 18 tmpfs，无 host port/生产卷/真实凭据。
- R3：通过当前上游的 /sign_in HTML 正常响应及实际token登录表单证明 HTTP 就绪；回读新数据库的 schema_migrations 和核心表，证明真实迁移。
- R4：数据库/应用提前退出、HTTP 未就绪、迁移缺失和有界超时均非零退出；成功、失败、超时和取消都清理独立容器、网络与自动生成的卷。诊断仅固定原因与必要状态，不打印运行配置或原始容器日志。
- R5：最小离线回归覆盖 success、提前退出、HTTP/数据库迁移失败、超时、阻塞 Docker 取消及清理；实际运行本次构建镜像并保存脱敏证据。云端双架构尚未完成时明确标待验证。
- AC1：本机实际默认入口启动成功，新临时库完成迁移，/sign_in 有意义响应成功，退出后无测试资源残留。
- AC2：故意破坏镜像默认入口或就绪行为时检查失败且清理；离线回归也验证错误状态与有界等待。
- AC3：两架构 workflow 中检查必须早于 docker save；相关 Python/语法/空白检查通过，实际 CI 结果单独记录。

## 范围外

不实现父任务尚待收敛的自动合并、beta 标签、Bark 或生产部署；不覆盖其他 agent 改动，不修改官方补丁或产品业务代码，不接真实车辆/地图服务。
