# README 文字与结构优化

## 目标

按用户反馈重写当前功能分支 README：减少机器生成的口吻，恢复面向使用者的项目结构。安装并使用用户指定的 Humanizer v3.0.0，继续在官方 README 基础上介绍高德新增功能。

## 范围

- 首页依次说明项目用途、高德地址功能、使用入口、官方功能与截图、版本维护、许可和致谢。删除会话进度、验收数字与内部接口细节，保留官方来源和 TRADEMARK 要求的非官方声明。
- 不将当前 v4.3.0 写成项目长期定位；准确版本以 upstream.json 为准。截图和来源链接仍固定已核对的官方提交。
- 版本说明须符合实际：定时检测上游稳定 release，审查后更新 pin，CI 自动应用补丁、测试和构建，main 手动请求发布。不声称新 release 会自动改 pin 或自动发布。
- 使用部分提供现有配置与源码构建入口，说明需补丁版 TeslaMate；不虚构已经发布的镜像。地址查询与客户端地图各自职责说明一次即可。
- docs/AMAP.md 只同步去除开头硬编码版本定位，其余接口、配置、备份和维护细节保留。
- 不改产品代码、工作流或 upstream.json；不合并、发布、部署或操作生产。技能安装在用户 catalog 完成，不把技能包或本机安装路径复制到仓库。

## 验收

- 实际读取指定版本 Humanizer，并完成初稿、自查与终稿；语言自然、标题清楚、链接有明确用途，无营销词或进度报告口吻。
- 官方功能、仪表盘、截图与许可/致谢保留；版本维护描述与实际 workflow 一致。
- 相对链接、锚点与 Markdown 检查通过，diff 无空白错误，独立审查无阻断。
- 在 feat/amap-adapter 提交并推送，核对最终 GitHub verify；原 PR 保持未合并。
