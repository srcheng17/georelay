# 技术设计：应用管理永久身份

## 1. 所有权与最小边界

永久数据归 TeslaMate/PostgreSQL 的 addresses：主键、稳定负 osm_id、精确原坐标及经验证的来源/路由元数据。新建降序 BIGINT 序列只管理编号高水位，不复制坐标。适配器保留 stdlib HTTP、供应商调用和缓存；无需数据库凭据。缓存可以保存坐标作为查询键，但不承担不可重建的映射职责。

新协议与地址模式仅在本项目适配器路径启用。默认 Nominatim 配置仍走原有 GET /reverse、GET /lookup，不把自定义参数发给官方服务。现有 NOMINATIM_LOCAL_IDENTITIES_ONLY 的具体兼容处理须由测试约束，不能让旧协议客户端收到静默错误成功。

## 2. 新地址路径

1. 应用规范化 WGS84 Decimal 坐标，不转换 GCJ-02、不舍入；先按坐标查找本地负身份地址。
2. 已有地址直接复用身份；地址文字依然只通过显式刷新更新，普通查询不自动改写历史文字。
3. 新坐标从应用拥有的降序序列取得候选编号；序列从已审计的旧编号范围之后继续，拒绝 BIGINT 溢出，允许失败造成编号空洞。
4. 在长数据库事务外调用适配器，发送候选身份、坐标、语言和供应商策略。供应商成功后才持久化有效地址。
5. 本地负 node 地址使用精确坐标唯一约束处理并发；插入冲突后读回胜出行，所有返回与持久化 raw 均对应胜出身份。不得以两个候选编号制造两个永久地址，也不得把失败写成占位记录。

原有 osm_id/type 唯一约束保留；新坐标约束只作用于本地负 node，排除正数历史地址和 Unknown。不能用 -addresses.id 重编号历史身份。坐标精度修复与历史审计必须先于启用唯一约束。

## 3. 刷新请求与响应

拟采用独立的版本化 JSON POST 协议，例如 /v1/reverse 与 /v1/lookup，沿用现有校验后的 origin/Finch pool。

- reverse 请求：版本、负 node 身份、原始 lat/lon、语言和策略；provider 覆盖保持现有取值。
- lookup 请求：最多 50 项，每项有身份、坐标、可信 OSM 来源及独立境外证据。语言在受验证 header 或统一 JSON 字段传递，不用长 URL 携带整批坐标。
- 响应：按请求顺序返回同一负身份和原坐标，附解析文字及供应商来源。严格核对请求/响应身份集合、坐标和来源；重复、缺项、额外项失败。
- 旧正身份按现有契约保留/跳过；不得从客户端正编号推断真实 OSM 对象来源。

新旧协议不匹配要明确报错；两镜像需作为兼容版本配套升级。新增 POST 路径必须检查 Tesla.Middleware.Logger、HTTP 错误与异常日志，禁止输出请求体、精确坐标或原始响应。协议最终签名在实现前的小型固定源码验证中确认；命名可调整，所有权、历史身份和错误合同不可改变。

## 4. 可信来源、区域证据与缓存

在 addresses.raw 中保留应用管理的命名空间元数据，包含先前可信 OSM 对象来源及独立 outside_mainland 证据；供应商切换或 raw 替换时有界合并该元数据。来源只来自成功验证的官方响应或已验证的旧 SQLite 导入，不能把 provider=osm 自动当成境外证明。明确区分显式大陆 OSM 与自动策略确认境外。

缓存按精确坐标、语言、策略及影响结果的可信来源上下文隔离；缓存模板不绑定客户端编号，响应时附本次请求身份和原坐标，避免并发候选编号污染。保持 TTL、OSM 单次/批量限流、4 线程批量预算、超时取消和固定错误。增加有界、低频的过期 cache 删除，健康检查验证缓存存储而不是永久身份库。清空缓存或限流文件不破坏业务身份；启动时继续遵守公共服务限流。

## 5. 历史迁移与启动门禁

迁移仅针对隔离恢复副本先验证；线上执行另行授权。

初始化明确区分从未使用旧身份库的 fresh 安装与 legacy 导入。fresh 需显式声明并审计无本地负身份/旧永久库；不能仅根据 PG 当前没有负地址自动初始化，因为旧 SQLite 可能已有未引用的编号。legacy 必须验证完整历史高水位并导入后才启用新路径。

positions 原本也仅保留 6 位小数。高精度地址回填后，新请求若来自已落库 Position 的 6 位输入，应视为不同 canonical 点；演练覆盖这一复用边界，不按邻近位置或六位量化强行合并。坐标回填仅恢复可验证的原值，不使用供应商偏移或吸附坐标。

1. 在停写维护窗口取得 PostgreSQL 与旧 SQLite 的一致副本，旧库按在线 backup API/停服务方式复制，不直接复制活动 WAL 文件。
2. 先只读审计：负身份重复/类型、PG 与 SQLite 的匹配、坐标规范化与越界、6 位精度冲突、raw 与映射证据一致性、可信 OSM 来源和路由字段，以及 SQLite 的全部已分配高水位。
3. 将 addresses 的坐标类型扩为不限 scale NUMERIC；根据可靠 SQLite 或可核验 raw 回填原值。positions/轨迹不修改。证据缺失或冲突输出类别/计数并停止，不合并、不重编号。
4. 把必要来源/区域元数据导入同一地址行，保留数据库主键和 osm_id。SQLite 中未被 PG 引用的映射不制造空白地址，但编号高水位必须覆盖这些已分配项及 AUTOINCREMENT 历史高水位。
5. 从完整高水位初始化降序序列，再建立局部精确坐标约束和应用迁移完成标记。迁移未完成时禁止应用所有权路径分配新 ID，避免在自动启动迁移阶段抢先去重或重建身份。
6. 原子切换应用/适配器兼容版本；通过删除新缓存后的历史刷新检查，再按指南封存旧 SQLite。旧库只作为迁移/回滚档案，新服务不读写其永久表。

导出/导入工具默认只读预览，写入须显式 apply；只处理受控恢复副本文件和应用数据库连接，不输出坐标、地点、token、原始响应。导出含位置隐私，权限 0600，受控临时存放。批量验证先完成再提交；序列单向推进产生的空洞允许，不能因回滚复用可能已发出的编号。

原子性限定为单个地址写入和一次导入提交；lookup 响应必须整批完整或失败，缓存可保留已成功项。继续上游起终点独立解析、逐地址/跨批刷新，不新增整条行程或整次历史刷新回滚。默认 Nominatim 的 Unknown 路径保持原样，新适配器失败不进入该成功分支。

## 6. 回滚与主要风险

应用所有权模式开始分配新身份后，旧 SQLite 不含新增数据，因此仅回退镜像不可安全恢复旧模式。允许的回滚需恢复匹配的 PG/旧 SQLite 截止点，并明确新增数据边界；坐标降回 6 位会丢失新精度，禁止静默 down migration；本任务不设计跨版本在线双写或自动反向迁移。部署前保留受控备份并验证恢复流程。

主要风险是历史坐标精度、供应商切换后残留来源的完整导入、并发首次插入、全编号高水位和新旧协议错配。较大的上游地址补丁是本方案的维护代价；固定 tag/commit、严格 git apply 和最终 release 测试继续作为门禁。

## 7. 预期文件边界

- patches/：仅增加应用地址路径、数据迁移/序列、精确坐标约束、元数据保留与对应 ExUnit。
- adapter/server.py、tests/test_adapter.py：版本化请求、模板缓存、去除永久映射依赖和缓存清理。
- scripts/ 中实际需要的导出/审计/导入支持、地址 fixture/RPC 与镜像启动检查及对应测试：验证旧库迁移和最终 release。
- README.md、README.zh-CN.md、docs/AMAP.md、Compose/.env 示例、MODIFICATIONS.md 和 adapter 修改通知：同步所有权、版本兼容和操作合同，保留此前用户要求的删除。
- .trellis/spec/backend/contracts.md、quality-guidelines.md 及必要跨层指南：实施确认后更新新契约。当前 spec 记载的是旧结构，不把它误当成否决用户已选方向的理由。

具体触及的辅助文件以调用链需要为准，不为规划而创建框架或多套长期存储。

## 8. Release 集成

子任务 10-03-image-release-notes 独立维护 PRD/design/implement。沿用 exact source 固定版本，为完整双包发布记录源码、上游版本变化、可读本地条目与 floating 结果；不把 alias失败包装成总成功，不把 beta/陈旧来源设为 GitHub latest。写入由独立 trusted-main job 完成，候选文字仅作为数据；controller/updater/main收尾需包括记录，补录不重建固定镜像。

当前父任务的架构升级在 docs/changes/ 添加一条说明，包含身份归属、缓存可删除、配套协议升级、legacy/fresh流程、历史身份/坐标保留以及不可仅镜像降级的回滚边界。子任务可信记录器需在发布该架构版本前完成用户审阅启用；本地实施可并行，不因此扩大线上合并/发布/迁移权限。

首次 main没有writer及默认token对修改workflow的beta/陈旧source权限限制按子任务设计处理：bootstrap_not_enabled不计ready，真实能力未验证前不宣称全链路完成，不执行高权限候选writer、不偷偷换凭据或tag目标。
